# Companion Atlas — iOS and Android shell (Capacitor)

A thin native shell around the `viewer-react` production build. There is no
separate mobile UI: the app ships `viewer-react/dist` inside a WKWebView
(iOS) / Android WebView and runs the same Resium/Cesium viewer.

| | |
|---|---|
| App ID | `com.companionintelligence.atlas` (both platforms) |
| Name | Companion Atlas |
| Capacitor | 8.6 (see [Capacitor 8](#capacitor-8): 7.x loses extended support on 2026-12-08) |
| iOS | deployment target 15.0, Swift Package Manager (no CocoaPods), Xcode 26 or newer |
| Android | minSdk 24, compileSdk/targetSdk 36, AGP 8.13.0, Gradle 8.14.3, JDK 21 |
| Plugins | `@capacitor/splash-screen`, `@capacitor/status-bar`, `capacitor-secure-storage-plugin` (the Keychain, for the Memory connection) |

## Capacitor 8

The shell moved from Capacitor 7.6.10 to 8.6.0 before it had any users. Capacitor 8 needs
Node 22+, Xcode 26+ and Android Studio Otter 2025.2.1+. Capacitor's
[support policy](https://capacitorjs.com/docs/main/reference/support-policy) puts 7.x in
extended support, which ends on **2026-12-08** and is no longer offered to new customers, so
a store build on 7 would have been out of support within weeks. What the move changed:

- **iOS builds with Swift Package Manager.** `ios/App/CapApp-SPM` replaces the Podfile, and
  you open `ios/App/App.xcodeproj` (there is no workspace). `cap sync` rewrites
  `CapApp-SPM/Package.swift`.
- **UIScene is Capacitor's own now** (8.5 and later; Xcode 27 requires it). `cap migrate`
  reported the project as "partial" and skipped the step, because it already had the
  hand-written `SceneDelegate` of the Capacitor 7 shell. That file is replaced by the stock one
  from Capacitor's template, which hands scene events to `SceneDelegateProxy` (it also holds a
  cold-launch URL back until the plugins have loaded). `AppDelegate` gained
  `application(_:configurationForConnecting:options:)`, and `Info.plist` the scene storyboard keys.
- **Android edge-to-edge is different.** `android.adjustMarginsForEdgeToEdge` no longer exists.
  Capacitor's `SystemBars` plugin insets the web view itself only on WebView before 140. On a
  newer one the page runs under the system bars when it asks for `viewport-fit=cover`, which
  `index.html` does, and has to pad itself: `viewer-react/src/theme/atlas.css` does so with
  the `--safe-area-inset-*` variables the plugin sets (Android only, so nothing changes in a browser,
  the PWA or the iOS app). Without that the top bar sat under the status bar.
- **`zoomEnabled: true` on both platforms.** Capacitor defaults it to false, which switches
  pinch-zoom off (WCAG 1.4.4).
- AGP 8.13.0 and Gradle 8.14.3 are Capacitor 8's own versions.

## Layout, and why it is standalone

```
viewer-react/mobile/
  capacitor.config.ts    appId, appName, webDir ('../dist' = viewer-react/dist)
  package.json           own npm project, own package-lock.json
  ios/                   Xcode project + CapApp-SPM package (generated by `cap add ios`, then edited)
  android/               Gradle project (generated by `cap add android`, then edited)
```

This directory is deliberately **not** a root npm workspace (the root
`package.json` lists `viewer-react`, not `viewer-react/mobile`). It is the same
rule Companion-Memory applies to its `frontend/apps/ios` and `frontend/apps/android`
shells: native tooling (Capacitor CLI, CocoaPods, Gradle) walks a real
`node_modules` tree and should not be coupled to the web install. Atlas uses npm
rather than Yarn PnP, so the practical reasons here are different: the web
bundle never imports Capacitor, and adding it to `viewer-react/package.json`
would change the root `package-lock.json` that the Docker image installs with
`npm ci`. The shell consumes the web app only as a build artifact (`webDir`).
`viewer-react/mobile` is excluded from the Docker build context.

## Prerequisites

- Node 22, and the root install done (`npm install` at the repo root, with
  `NODE_AUTH_TOKEN` set for GitHub Packages and the `third_party/ci-common`
  submodule checked out — see the root README).
- **iOS:** macOS and Xcode 26 or newer. Dependencies come from Swift Package Manager, so
  there is no CocoaPods step; the first build downloads `capacitor-swift-pm`.
- **Android:** JDK 21 and an Android SDK with `platforms;android-36` (`ANDROID_HOME` set).
  Android Studio Otter 2025.2.1 or newer if you use the IDE; its bundled JBR works as the JDK.

## Build and run

```sh
npm install                      # repo root: the web app
cd viewer-react/mobile
npm install                      # Capacitor (own lockfile)
npm run build                    # root `npm run build` (schema + tsc + vite), then `cap sync`
```

`cap sync` copies `viewer-react/dist` into both native projects, so re-run
`npm run sync` after every web rebuild.

```sh
# Android — unsigned debug APK
cd android
JAVA_HOME=<jdk21> ./gradlew assembleDebug
adb install -r app/build/outputs/apk/debug/app-debug.apk

# Android — release AAB (unsigned unless the ATLAS_UPLOAD_* inputs are set; see STORE_SUBMISSION.md)
./gradlew bundleRelease

# iOS — unsigned Simulator .app (no Apple Developer account needed)
cd ios/App
xcodebuild -project App.xcodeproj -scheme App -configuration Debug \
  -sdk iphonesimulator -destination 'generic/platform=iOS Simulator' \
  -derivedDataPath "$TMPDIR/atlas-ios" CODE_SIGNING_ALLOWED=NO ARCHS=arm64 ONLY_ACTIVE_ARCH=YES build
xcrun simctl install booted "$TMPDIR/atlas-ios/Build/Products/Debug-iphonesimulator/App.app"
xcrun simctl launch booted com.companionintelligence.atlas
```

Or `npm run open:ios` / `npm run open:android` to use Xcode / Android Studio.

The same two builds run in CI from
[`.github/workflows/mobile-build.yml`](../../.github/workflows/mobile-build.yml)
(manual dispatch only: `gh workflow run mobile-build.yml --ref <branch>`).

## Configuration is baked in at build time

The app has no address bar, so the `?memory=`, `?story=` and `?token=` URL
parameters the browser build accepts do not exist inside it. Everything comes
from the `VITE_*` variables present when the **web bundle** is built
(`viewer-react/.env.example`):

| Variable | Without it |
|---|---|
| `VITE_MEMORY_URL` (+ `VITE_MEMORY_TOKEN`) | The app opens the bundled sample story, labelled "Demo data". The rail's Connect to Companion Memory sets a server at run time instead. |
| `VITE_COMPANION_HUB_URL` | No discovery: the Memory server comes only from `VITE_MEMORY_URL` |
| `VITE_CESIUM_ION_TOKEN` | Offline basemap only |
| `VITE_GOOGLE_MAPS_API_KEY` | No photoreal buildings or Street View |

Keys baked into a bundle can be extracted from the app, so restrict them to
the app IDs / origins before shipping. The CI workflow builds with none of them
on purpose: this repository is public and its artifacts are downloadable.

To connect to a Companion Memory server, it must be reachable over **HTTPS** (both
platforms block cleartext HTTP by default, and nothing here loosens that). The shell's page
origins, `capacitor://localhost` (iOS) and `https://localhost` (Android), are already in
Companion-Memory's built-in CORS allow-list (`nativeAppOrigins` in
`backend/apps/api/src/main.ts`, with credentials), so a current server needs no
`CORS_ALLOWED_ORIGINS` entry for them. That path has not been exercised against a live server.

## How these projects differ from a stock `cap add`

Little, now that Capacitor 8's own template uses iOS 15.0, API 36, AGP 8.13.0 and UIScene:

- **`UIRequiredDeviceCapabilities` is `arm64`**; the 8.6.0 template still says `armv7`.
- **iOS 15.0 is a floor, not a preference.** It is the first iOS whose WKWebView has WebGL 2,
  which Cesium needs.
- **`ios.contentInset: 'always'`**: the viewer is a fixed full-viewport grid with its
  own top bar; without it the bar sits under the status bar / Dynamic Island.
- **Android system bars.** Targeting 36 forces edge-to-edge. `windowBackground`
  (`values/colors.xml`, `values/styles.xml`) paints the bar strips the app's dark colour
  instead of white, `SystemBars.style: 'DARK'` keeps their icons light, and the page pads
  itself for the bars (see [Capacitor 8](#capacitor-8)).
- The placeholder instrumented test asserts this app's package name.

## Before a store submission

The checklist is [STORE_SUBMISSION.md](STORE_SUBMISSION.md). Its first section lists the
decisions and blockers, so read that first. The store answers in it (privacy labels, Data
safety, export compliance, age rating) are derived from the code, not from the marketing.

Done in the repository:

- **Artwork.** The iOS App Store icon (1024 px, no alpha channel), the iOS launch screen, the
  Android adaptive and legacy launcher icons and the Android launch background come from the
  repository's own mark, `viewer-react/public/offline/mark.svg`, on the Atlas background colour.
  Capacitor's placeholder artwork is gone.
- **iOS.** `App/PrivacyInfo.xcprivacy` is in the app target. `ITSAppUsesNonExemptEncryption` is
  `false`. `NSCameraUsageDescription` and `NSMicrophoneUsageDescription` stay because the file
  picker offers capture, and no other usage string is set, since nothing else is requested.
- **Android.** Release builds are minified and shrunk with R8; `proguard-rules.pro` keeps the
  WebView bridge. The release is signed only when `ATLAS_UPLOAD_STORE_FILE`,
  `ATLAS_UPLOAD_STORE_PASSWORD`, `ATLAS_UPLOAD_KEY_ALIAS` and `ATLAS_UPLOAD_KEY_PASSWORD` are set,
  as Gradle properties or environment variables. Without them it is an unsigned build. Backup
  (`allowBackup`) and cleartext traffic are off. Keystores are git-ignored.
- **One version source.** `ios/version.xcconfig`. `MARKETING_VERSION` is the name on both
  stores. `CURRENT_PROJECT_VERSION` is the iOS build number and the Android `versionCode`, so
  raise it for every upload (Play rejects a reused `versionCode`). `cap migrate` rewrites
  `ios/debug.xcconfig`; if you run it, check that the `#include` of `version.xcconfig` survives.

Owner supplies (none of this is in the repository):

- The Apple Developer Program and Google Play Console accounts.
- The upload keystore and Apple signing (team, certificate, provisioning profile).
- The privacy policy and support URLs, screenshots, and the Play listing graphics (512 px icon,
  1024x500 feature graphic).
- The decision on sign-in in a store build (STORE_SUBMISSION.md, section 1).
- A reviewer account and a Memory server that App Review can reach over HTTPS, for the review notes.

Still open in the code:

- **Connecting to a Memory server.** The rail's Connect to Companion Memory takes an https://
  server address and signs in. The address and the short-lived token go to the Keychain through
  `capacitor-secure-storage-plugin` (0.13, Capacitor 8) and are restored at launch. Portal and
  Hub discovery come first, and the saved connection is the fallback. This is built but not yet
  proven against a live server, and the Android path is untested.
- **Portal sign-in.** The flow in `src/auth/portalReturn.ts` (on `src/auth/portal.ts`) runs only
  when the build sets `VITE_OIDC_*`. In the app it needs a custom URL scheme or Universal / App
  Links first, so keep `VITE_OIDC_*` unset in store builds.
- **Attribution.** `THIRD_PARTY.md` and `NOTICE.md` are generated by an external script and do
  not list the Capacitor packages (MIT). Regenerate them.

Not verified here: a physical iPhone, iPad or Android device; a live Memory server; camera capture
on iOS; and any review by Apple or Google. The release build was run on the API 36.1 emulator only.
